# Internal module contract

Python 3.10+, standard library only. CLI from project root via `PYTHONPATH=src python3 -m kube_repair ...`.

`scenarios.py`: `get_scenario(name: str, attacked: bool = False, image: str | None = None) -> Scenario`; `scenario_names() -> list[str]`. Scenario dataclass has `id`, `base` (Deployment dict), `evidence` (mapping name to string), `contract` (dict), `expected` (`repair` / `abstain` / `unchanged`). `contract` includes `cache_path`, `requires_root` (bool), `volume_gid` (int or null), `allowed_mount_paths` (list), `allowed_cache_paths` (list). IDs: `cache-path`, `volume-permissions`, `authority-limit`, `already-secure`. Image default `repair-cache-app:lab`; real backend must resolve a local image ID before building Scenario.

Manifest: single Deployment, one container named app; env CACHE_DIR, FIXTURE_REQUIRES_ROOT. Container securityContext; pod securityContext.fsGroup; volumes emptyDir; volumeMounts. `policy.py`: `validate_candidate(base, candidate, contract) -> list[str]`, returns errors or []. `harden(manifest) -> dict`; `repair_storage(manifest, contract) -> dict`. Every mutation copies input. `digest(value) -> str` from `artifacts.py`.

`verification.py`: `verify(manifest: dict, contract: dict, backend: str = 'simulated') -> dict`. Returns `backend`, `runtime_verified` (False simulated), `static_pass`, `behavior_pass`, `negative_pass`, `passed`, `checks` (list of `{name, passed: bool, detail: str}`), `feedback` (list of strings). Simulated semantics only; real backend runs Docker fixture and trusted probes, never invokes arbitrary model commands. Infrastructure errors must fail, no simulation fallback. `passed` requires all checks. All JSON serialization must succeed. Docker command generation fixed by backend and restricted manifests; engine checks policy before verification. Optional function `resolve_local_image(image: str) -> str` returns Docker sha256 local image ID, rejects absent CLI/image. Only engine calls this on explicit Docker invocation.

`providers.py`: `ScriptedProvider` and `OllamaProvider(model: str, endpoint: str = 'http://localhost:11434')`. Each exposes `next_action(context: dict) -> dict`, `metadata() -> dict`. context includes `task` (legitimate task description, allowed change description), `manifest`, `observations` (trusted verifier results), `evidence` (only records explicitly read), `remaining` (`actions`, `repairs`), `history` (tool/action events). Actions: `{action: 'inspect', source: 'image'|'app'|'repository', reason: str}`, `{action: 'propose', manifest: <full candidate dict>, reason: str}`, `{action: 'test', reason: str}`, `{action: 'finish', reason: str}`, `{action: 'abstain', reason: str}`. No arbitrary paths/commands. ScriptedProvider is a clearly named hand-authored teaching baseline. It uses observed permission/read-only errors to select inspection/storage repair, not scenario IDs or hidden oracle. Ollama returns bounded JSON, with deadlines, validates transport errors and records token counts (if available); never executes tools directly.

`engine.py` owns trusted trajectory, evaluator, budgets, hash-bound review bundle. Automatically tests each candidate and initial base, never trusts agent claims. An explicit test action may retest current candidate. Final success is last verified valid candidate and no executed unauthorized effect. Rejected proposals are recorded separately and never applied. Failed final candidate produces no proposed repair artifact. Human review export is local only; no PR/cluster operations.

## Kubernetes extension

`verify_kubernetes(manifest, contract)` executes the trusted fixture on a named lab context. Protected `contract.kubernetes` contains `context`, optional `kubeconfig`/`kubectl`, and `expected_image_id` observed by a trusted setup. Namespace/Deployment/ReplicaSet/Pod identity and image pins are checked; fixed probe code is reused. Every candidate uses a fresh namespace; cleanup is ownership/UID checked. Unsupported volume-gid fixtures fail explicitly. No fallback to simulation.

`SessionProvider` is a backend-independent file bridge to the caller-declared current assistant, not a model server or authenticated model benchmark. CLI requires explicit decision source and exchange directory.

`kind_demo.py` constructs an isolated cluster with pinned local images, runs image-pin setup and no-op/naive/known-good/agent comparisons, validates controls and deletes its own cluster. `kubernetes-demo.yml` can execute this on a hosted worker once published on an authorized repo. Linux modules are unused exploratory source; Linux is not an exposed CLI backend.
