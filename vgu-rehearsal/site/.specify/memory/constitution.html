VGU Rehearsal Materials Constitution

Core Principles

I. Outputs at the point of use

Every worked notebook MUST retain fresh execution counts and inspectable results at the exact path linked from the rehearsal entrypoint. A log elsewhere does not satisfy delivery. Untouched student exercises MUST be labelled incomplete; expected TODO errors MUST never count as passes.

II. Requirements govern every teaching artifact

The invitation and supplied job description govern topic, audience, language, timing and duties. Slides, embedded presenter notes, scripts, labs and assessment MUST tell the same story. Advanced work MUST be explicitly optional. No artifact may claim that a timed lecture proves mastery.

III. Checks test behavior and the delivered artifact

Worked notebooks MUST execute in fresh kernels without allowed errors. Tests MUST target the canonical implementation and student tests MUST target student functions. Verification MUST read saved files after execution and inspect the rendered deliverables, including edge-case behavior.

IV. Claims require matching evidence

Every historical numerical research claim MUST cite a primary record with matching metric, population and scope. Group results MUST be distinguished from personal contributions. Unknown claims MUST be omitted from presentation speech or explicitly retained as candidate confirmations outside the presentation. Human rehearsal, HR confirmations and student comprehension MUST never be marked completed by software checks.

V. One practical offline rehearsal route

One START_HERE document MUST identify the current decks, scripts and worked notebooks. PDFs and saved notebook results MUST support rehearsal without live installation or external data access. The package MUST explain why the ideas matter, how the mathematics becomes code, and how a student can build a controlled project with a baseline and held-out evaluation.

Delivery Constraints

Generated files remain within experiments. Shared data stays untouched. Original notebook code is preserved when adding outputs; exact prior originals are backed up. Corrected content lives in REHEARSAL_READY. No email, application submission, public publication or personal factual confirmation is implied by this work. The local Spec Kit revision and actual commands are recorded.

Workflow and Quality Gates

Use the installed Spec Kit templates for specification, plan and tasks. Map every requirement to an artifact and a verification result. Review requirement quality separately from implementation completion. Run consistency analysis, implement the tasks, then assess convergence against saved artifacts. A missing obligation creates a traceable corrective task; checked boxes alone are not evidence. No claim of convergence extends to the candidate's unobserved live rehearsal.

Governance

Version principles semantically and record amendments with their rationale. The user's task and workspace instructions take precedence. All requirements MUST be verified or explicitly bounded before handoff; unresolved candidate facts remain in a separate human-action checklist. This constitution governs material preparation and delivery, not university certification.
