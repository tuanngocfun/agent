1. Test causality by changing the future

A triangular picture alone cannot prove the implementation uses the mask correctly. Change keys and values at positions 3–4 by a large amount and verify that outputs at positions 0–2 do not change. The unmasked control should change; otherwise the experiment would not diagnose the mask.

2. Padding keys, fully blocked queries, and gradients

A padding key mask prevents invalid source positions from contributing to attention. Here our explicit all-masked policy is zero weights and zero output; it avoids NaNs but is an implementation choice. Valid rows sum to one. Fully blocked rows sum to zero and should not be treated as valid predictions. Additive masks are used throughout this teaching API; boolean conventions vary between PyTorch attention APIs.

In [3]

3. Loss padding is a separate operation

ignore_index=PAD removes padding labels from the mean cross-entropy and gives those logits zero loss gradient. It does not add an attention mask. Our all-ignored-label policy is a differentiable zero loss. In a real training loop, report supervised token counts and usually avoid optimizing an empty batch.

4. Actually run greedy and beam search on a counterexample

Fix a two-token horizon, with no EOS in this control. The first distribution is P(A)=0.6P(A)=0.6P(A)=0.6, P(B)=0.4P(B)=0.4P(B)=0.4. After A, P(X∣A)=P(Y∣A)=0.5P(X|A)=P(Y|A)=0.5P(X∣A)=P(Y∣A)=0.5; after B, P(X∣B)=1P(X|B)=1P(X∣B)=1. The complete sequence probabilities are AX=0.30, AY=0.30, BX=0.40.

We feed these distributions through the same generation functions used by the image-to-sequence demo. Beam width is 3, length exponent alpha=0, so ranking uses the raw sum of log probabilities. Ties under A may choose X or Y; both have probability 0.30. The current PyTorch argmax control selects X. Ask: why does the locally best first token lose here? Does a higher model score establish real-world correctness?

5. EOS is a separate stopping rule

The fixed-horizon control above intentionally excludes EOS. Now test two rows that finish at different times. Row 0 emits EOS immediately; row 1 emits 1, 1, EOS. The finished row is padded while the other continues. Metrics remove the leading BOS and stop at the first EOS. Internal BOS or pre-EOS PAD remains a prediction error.

6. Optional: temperature sampling from the same logits

For each temperature, use the same base logits log⁡[0.55,0.30,0.15]\log[0.55,0.30,0.15]log[0.55,0.30,0.15] and compute softmax(logits/temperature). Lower temperature concentrates this distribution; it does not add evidence that the modal token is correct. Sample counts vary with the generator. A seed makes this demonstration repeatable in this environment.

In [7]
base_logits=torch.log(torch.tensor([.55,.30,.15]))
for temperature in (.5,1.,2.):
    probabilities=torch.softmax(base_logits/temperature,-1)
    draws=torch.multinomial(probabilities,300,replacement=True,generator=torch.Generator().manual_seed(11))
    counts=torch.bincount(draws,minlength=3)
    print('temperature:',temperature,'probabilities:',[round(x,4) for x in probabilities.tolist()],
          '300 sample counts:',counts.tolist())
    assert counts.sum()==300 and probabilities.argmax()==0
