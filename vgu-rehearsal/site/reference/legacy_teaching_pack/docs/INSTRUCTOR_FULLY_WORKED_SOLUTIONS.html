T1.C: Masking is not target shifting (5/5)

A=[10001/21/2001/31/31/301/41/41/41/4].A=\begin{bmatrix}1&0&0&0\\1/2&1/2&0&0\\1/3&1/3&1/3&0\\1/4&1/4&1/4&1/4\end{bmatrix}.A=​11/21/31/4​01/21/31/4​001/31/4​0001/4​​.

Each row sums to exactly 1 in real arithmetic. exp⁡(−∞)=0\exp(-\infty)=0exp(−∞)=0, so forbidden entries become zero after softmax. This example is for zero logits; other logits produce different nonzero weights.

Step 2 — Shift target labels by one position

Full reference tokens: [BOS, I, love, AI, EOS]. Decoder input: [BOS, I, love, AI]. Targets: [I, love, AI, EOS].

At input position 0 the model predicts I; at position 1 it predicts love; at position 2 it predicts AI; at position 3 it predicts EOS. Shifted labels establish the learning objective; the causal mask establishes which input positions may influence a prediction. They are complementary, not interchangeable.

Step 3 — Why neither alone is enough

  • Without shift (labels equal inputs), a sufficiently expressive decoder can learn an easy identity-copy objective instead of forecasting the next token. Even correct masking cannot correct a misdefined target.
  • Without causal mask, the position predicting love may access the future decoder-input position where the token love itself already appears. This leaks ground truth. Such a model may exploit the leak; zero training loss is not guaranteed.
  • At inference, the model must use its own generated prefix. There is no ground-truth future target in the prefix.

Padding caveat. If a query has all keys masked, softmax over [−∞,−∞,… ][-\infty,-\infty,\dots][−∞,−∞,…] is undefined in the elementary implementation. Common solutions ensure a valid key per query, suppress padded query losses, or use a numerically stable attention kernel that handles the mask case explicitly. Do not set all forbidden logits to zero: exp⁡(0)=1\exp(0)=1exp(0)=1 would not mask them.

T2.A: Correct attention implementation (6/6)

The formula

Attention(Q,K,V;M)=softmaxj ⁣(QK⊤dh+M)⏟A with ∑jAij=1V\mathrm{Attention}(Q,K,V;M)=\underbrace{\mathrm{softmax}_{j}\!\left(\frac{QK^\top}{\sqrt{d_h}}+M\right)}_{A\,\mathrm{with}\,\sum_jA_{ij}=1}VAttention(Q,K,V;M)=Awith∑j​Aij​=1softmaxj​(dh​​QK⊤​+M)​​V

contains a precise operation sequence. Q @ K.transpose(-2,-1) computes the last two matrix axes while keeping the earlier dimensions for batch/head broadcasting. Divide by dh\sqrt{d_h}dh​​ before normalization. Add an additive mask with 000 for allowed and −∞-\infty−∞ for forbidden positions. Softmax on dim=-1 since the last dimension indexes keys. Finally take weights @ V.

import math
import torch

def attention(q, k, v, mask=None):
    # q [B,H,Tq,d], k [B,H,Tk,d], v [B,H,Tk,dv]
    logits = (q @ k.transpose(-2,-1)) / math.sqrt(q.shape[-1])
    if mask is not None:
        logits = logits + mask    # broadcast on B,H
    weights = torch.softmax(logits, dim=-1)  # across keys
    return weights @ v, weights

Shape example. If q,k,v=[2,4,4,4], logits=[2,4,4,4], weights same, output [2,4,4,4]. If k source length is 5 and v feature depth is 6, score [2,4,3,5], output [2,4,3,6].

Test invariant: weights.sum(dim=-1)==1 within numerical tolerance on rows with at least one valid key. Use torch.allclose with tolerance (floating-point error).

T2.B: Causal and padding mask correctness (6/6)

For query iii at absolute position p+ip+ip+i with cached prefix of length ppp, the allowed key positions are j≤p+ij\le p+ij≤p+i. Hence the general mask is

Mij={0,j≤p+i,−∞,j>p+i.M_{ij}=\begin{cases}0,&j\le p+i,\\-\infty,&j>p+i.\end{cases}Mij​={0,−∞,​j≤p+i,j>p+i.​

Create mask in PyTorch by comparing ranges, avoiding a shape bug when Tq≠TkT_q\ne T_kTq​=Tk​:

def causal_mask(Tq, Tk, past, device):
    qpos = torch.arange(past, past + Tq, device=device)[:,None]
    kpos = torch.arange(Tk, device=device)[None,:]
    return torch.where(kpos <= qpos, 0.0, float('-inf'))

For training without caching, Tq=Tk=TT_q=T_k=TTq​=Tk​=T and p=0p=0p=0. To mask padded keys, combine the causal mask with key-padding information: if valid_key[j] is false, set score at every query iii for key jjj to −∞-\infty−∞. For B batches, expand padding mask to [B,1,1,Tk] before broadcasting against [B,H,Tq,Tk]. Query-padding positions should be excluded from the loss using ignore_index, not merely prevented from attending to keys.

Counterexample to flawed masking. If future logits are set to 0 rather than -inf before softmax, their exponentials become 1, giving positive probability to forbidden future keys. If a row has no valid keys at all, naive softmax produces undefined values; the loss must ignore these query positions or construct a safe non-empty allowed set.

Test for regular causal rows:

T2.D: An intellectually honest future-leakage demonstration (4/4)

A model trained without a target causal mask can use decoder input position t+1t+1t+1 when producing logits at position ttt. With teacher forcing, that input position contains the reference target yt+1y_{t+1}yt+1​, so the input supplies an answer that will not be available during left-to-right inference.

Concrete illustration: let decoder input token IDs be x=(BOS,a,b)x=(\mathrm{BOS},a,b)x=(BOS,a,b) and targets y=(a,b,EOS)y=(a,b,\mathrm{EOS})y=(a,b,EOS). Suppose an artificial attention circuit at output position 0 puts weight 1 on input position 1, whose embedding identifies aaa. A classifier can then predict target aaa almost trivially. Under a causal mask, output position 0 must attend only to BOS; the future aaa is not accessible from the attention mechanism. This is a constructed causal demonstration, not evidence that training always collapses to zero loss without a mask. Empirical results depend on model, optimization and data.

Demonstration with one-hot logic (no training needed):

# Artificial unmasked head: output at position 0 copies x[1].

# A causal head cannot select x[1] when predicting at position 0.

To study the effect empirically, train a toy model with/without mask under identical random seeds and compare held-out autoregressive generation, not only training loss. Never promise a particular training-loss curve as a guaranteed outcome.

Marking: explicit target alignment 1; leak mechanism 2; no universal claim 1.

T3.C: KV-cache and GQA resource accounting (7/7)

A decoder layer processes queries Q∈RB×Hq×T×dhQ\in\mathbb R^{B\times H_q\times T\times d_h}Q∈RB×Hq​×T×dh​, while keys and values in GQA have shape [B,Hkv,T,dh][B,H_{kv},T,d_h][B,Hkv​,T,dh​]. With full attention, the layer recomputes K,VK,VK,V for all tokens if a naive implementation runs the entire prefix again at every new step. KV caching stores previously computed K,VK,VK,V so a new token only requires new projections for that step.

Exact cache size formula

Suppose we have LLL decoder layers, BBB sequences, TTT cached positions, HkvH_{kv}Hkv​ KV heads per layer, dhd_hdh​ channels/head and bbb bytes/element. There are two cached tensors K and V. Therefore

KVBytes=2 B L T Hkv dh b.\boxed{\mathrm{KVBytes}=2\,B\,L\,T\,H_{kv}\,d_h\,b}.KVBytes=2BLTHkv​dh​b​.

For B=2B=2B=2, L=6L=6L=6, T=128T=128T=128, Hkv=2H_{kv}=2Hkv​=2, dh=4d_h=4dh​=4, bf16 b=2b=2b=2 bytes:

2⋅2⋅6⋅128⋅2⋅4⋅2=49,152 bytes=48 KiB.2\cdot2\cdot6\cdot128\cdot2\cdot4\cdot2=49,152\text{ bytes}=48\text{ KiB}.2⋅2⋅6⋅128⋅2⋅4⋅2=49,152 bytes=48 KiB.

Why GQA saves memory. Standard MHA with Hkv=Hq=4H_{kv}=H_q=4Hkv​=Hq​=4 stores twice as many key/value heads as GQA with Hkv=2H_{kv}=2Hkv​=2, holding all else fixed. MQA with Hkv=1H_{kv}=1Hkv​=1 stores one quarter as many as full MHA in this configuration. It can alter model behavior; this comparison is only a memory-accounting fact.

Derive the shapes of cached decoding

At current time ttt, for one new token Qnew:[B,Hq,1,dh]Q_{new}:[B,H_q,1,d_h]Qnew​:[B,Hq​,1,dh​]. Cached keys Kcache:[B,Hkv,t−1,dh]K_{cache}:[B,H_{kv},t-1,d_h]Kcache​:[B,Hkv​,t−1,dh​] and newly computed Knew:[B,Hkv,1,dh]K_{new}:[B,H_{kv},1,d_h]Knew​:[B,Hkv​,1,dh​] concatenate to [B,Hkv,t,dh][B,H_{kv},t,d_h][B,Hkv​,t,dh​]. The corresponding values do likewise. Each KV head is reused for a group of Hq/HkvH_q/H_{kv}Hq​/Hkv​ query heads. After expansion, score shape becomes [B,Hq,1,t][B,H_q,1,t][B,Hq​,1,t], and the output [B,Hq,1,dh][B,H_q,1,d_h][B,Hq​,1,dh​].

Full-prefix vs cache equivalence

For deterministic model in eval mode, with exactly the same weights, causal mask, position offsets and normalizations, the final hidden output for time ttt computed with a cache must match the final position of a full-prefix calculation within floating-point tolerance. The shipped test test_cached_matches_full does this for Hkv=1,2,4H_{kv}=1,2,4Hkv​=1,2,4 using RoPE; run pytest -q.

Complexity qualification. At each new step, the attention score for one query against ttt cached keys costs O(tdh)O(t d_h)O(tdh​) per head, compared with recalculating the entire prefix's t×tt\times tt×t attention, O(t2dh)O(t^2 d_h)O(t2dh​) for the attention-score part. This is not a claim that the entire model step is O(t)O(t)O(t)—linear projections and MLPs also cost computation, and total latency depends on hardware/memory bandwidth/batching. Storing KV cache increases memory consumption linearly with TTT.

T4.C: Autoregressive inference and beam search (5/5)

At test time there is no ground-truth prefix. Begin with BOS and iterate

H. Common mistakes, diagnostics and actionable feedback

Mistake 1: Transpose wrong axes. If K.transpose(1,2) rather than K.transpose(-2,-1), matrix multiplication can silently mix heads/time dimensions when some sizes match by coincidence. Assert shape after each operation and test with distinct B,H,T,dhB,H,T,d_hB,H,T,dh​.

Mistake 2: Softmax on the wrong dimension. Each query must distribute weights over keys. Test weights.sum(-1); if it doesn't equal ones, softmax or masking is suspect.

Mistake 3: A boolean mask with inverted convention. PyTorch APIs differ: in some attention APIs True denotes blocked keys, elsewhere it denotes allowed keys. Document the convention explicitly and inspect a tiny 3×33\times33×3 example.

Mistake 4: No shifted targets. A decoder training to predict its own input can learn copy identity rather than next-token generation. Compare ids[:,:-1] vs ids[:,1:] and inspect pairs.

Mistake 5: Missing RoPE absolute offsets with cache. Cached incremental and full-prefix outputs diverge, even with identical weights. Use start_pos=cache_len for queries and fresh keys and assert parity.

Mistake 6: Comparing speed without synchronized timing. CUDA kernels run asynchronously. Synchronize for measurement and report hardware. CPU warm-ups and tiny models make speed claims especially noisy.

Mistake 7: Claiming historical OCR generalization from synthetic glyphs. Real Hán–Nôm requires diverse scripts, segmentation, page-layout modeling, annotation provenance, book-level splits, domain shift and human-reviewed metrics. This mini-project teaches mechanics only.

Mistake 8: Presenting unverified coursework as official VGU. All material in this archive is proposed, and references are public external course sources.
