Design decisions

  • Decision: save fresh outputs in original notebooks as well as canonical worked notebooks. Rationale: the user opens original paths;separate audit copies did not satisfy that interaction. Exact prechange files are backed up;student stubs remain unfinished.
  • Decision: provide eight complete runnable reference notebooks, including completed legacy Student filenames, and separate independent practice in teaching/STUDENT_PRACTICE.md. Rationale: every supplied runnable file must demonstrate successfully; fresh unanswered tasks belong in a Markdown handout. This decision supersedes the former blank executable scaffolds.
  • Decision: generate PPTX/PDF from the same structured slide source and typed layout;embed fresh matching notes. Rationale: old copies drifted in timing, claim qualifiers and examples. Avoid a system-wide office-suite installation.
  • Decision: keep only primary-evidence historical numbers in speech;record unknowns outside the talk. Rationale: authorship does not prove personal code ownership;source records support only particular metrics.
  • Decision: use fixed known-template glyphs as an explicitly limited mechanics demo;compare decoders on identical cases and add a nearest-template baseline. Rationale: toy success cannot establish a need for autoregression or real OCR quality.
  • Decision: package readiness is material readiness, with human rehearsal/HR status separate. Rationale: Spec Kit structures obligations;it does not certify comprehension or unobserved actions.

Alternatives considered: keep results only in review copies (fails user's interaction);silently complete student tasks (invalid assessment);repeat unsupported metrics with caveats only in a hidden appendix (misleading speech);install global packages (unnecessary);adopt a large online model for a 30-minute introduction (unnecessary dependency).
